# P0 现状与架构决策

2026-11-13 核对 origin/main：6576eee（已 fetch 校验）。之前为无依赖 Node 静态站点，8款商品和 localStorage 演示订单，3个原有规则测试。原 index.html、css/、js/、test/ 原样保留，首页路由不变。

新增原生小程序（WXML/WXSS/JS），不是 H5。商家与骑手 Web 工作台共用角色隔离接口。业务服务独立于 HTTP，可以在授权后提取到云函数。当前不包含可直接部署的微信云开发身份/数据库适配；cloudfunctions/service.js 是业务核心，不能误认为已经上线的微信云函数。

选择零 npm 运行时依赖，先完成本机模拟闭环。Node 24 / Python 3；本机SQLite数据库按事务保存，接口串行执行并在失败时回滚内存，重启保留商品订单；数据库有订单幂等唯一索引。仅单进程服务实例，不可多副本共用内存缓存。生产必须适配云事务数据库与条件库存扣减。

角色由服务端会话决定，不从请求 data 接收角色。默认需独立角色令牌；会话一小时失效。DEMO_MODE=true 可免令牌选择演示身份，只允许本机开发。当前一个演示顾客/骑手；真实微信 openid 登录、多用户会话、组织授权未接入，不能投入真实经营。

价格以分为整数，商品下单时服务端复核价格和库存；起送20元，运费6元，满59元免运费。创建待付订单预留库存，15分钟未支付释放。状态：pending→paid→picking→assigned→delivering→delivered；pending/paid 可取消，已支付取消需确认模拟退款。售后仅已送达可申请，管理员确认模拟退款，绝不接触真实资金。

称重规则：本版按展示规格的固定包装计价；“斤/公斤”可作销售单位，但不支持实际称重后自动结算。计划采用估重预收，配货实际重量小于预估时生成差额退款草稿由商家确认；超重不得自动多扣款，需减量或顾客重新确认订单。称重差额执行功能仍待开发，后台不得把估重当成实际重量。

AI 默认本地规则，不调用外部模型。导入不会猜缺失信息；图片只有来源、商用授权证据、名称规格及已知品牌条码都匹配后进入草稿，应用仍需管理员确认。未取得授权的图片只保留待审核元信息，不抓取、不下载。模型网关仅可注入供应商实现，提供预算/限流/超时/切换和个人信息标记拦截；标记不能代替生产环境 DLP。
